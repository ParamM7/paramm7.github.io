GPU-Accelerated 2D NS Solver
— fractional-step FVM with CUDA kernels.

A 2D incompressible Navier–Stokes solver built from scratch in Python/CuPy with custom CUDA kernels — Chorin fractional-step, Rhie-Chow pressure correction, IBM geometry, and swappable Krylov pressure backends running entirely on GPU.

Context

A personal research and learning tool: a complete 2D incompressible Navier–Stokes solver written from scratch in Python with CuPy, keeping all computation on the GPU. The motivation was to build a solver understood at every layer — from the finite-volume flux assembly in CUDA C++ to the pressure Poisson matrix construction in CSR format — to complement the OpenFOAM-based research work and develop practical fluency in GPU numerical computing.

The solver is structured around a frozen FlowPreset dataclass: switching flow cases is a single line change, and all domain parameters, solver tolerances, geometry, and boundary condition profiles are encapsulated in the preset so no other file requires editing.

Numerical Method

Chorin's fractional-step (projection) method on a uniform Cartesian staggered grid with finite-volume discretisation. Each time step proceeds through four stages:

  • Momentum predictor: Explicit Euler step solving the advection–diffusion equation without pressure. Convective fluxes use first-order upwind (FOU); diffusive fluxes use central differencing. Implemented as a CUDA RawKernel with per-cell metric scaling for variable mesh spacing.
  • Rhie-Chow correction: Face velocities are reconstructed with a Rhie–Chow interpolation to suppress the checkerboard pressure–velocity decoupling instability. The correction accounts for the difference between the local face pressure gradient and the cell-centred gradient interpolated to the face.
  • Pressure Poisson equation: The PPE RHS — divergence of the predicted velocity field scaled by ρ/dt — is assembled on-GPU. The system A·p = −b (A = negative discrete Laplacian, SPD) is solved by the configured backend.
  • Velocity corrector: Cell-centred velocities are corrected by the pressure gradient to enforce incompressibility: u ← u* − (dt/ρ)∇p.

IBM (immersed boundary method) masking zeroes velocities inside body cells after each predictor and corrector step. Local mesh refinement around the body and in the wake is supported through the mesh options dictionary in each preset.

CUDA Kernels

Three primary kernels are compiled at solver startup via cp.RawKernel with --use_fast_math. All operate on the full 2D domain in a single kernel launch using a 16×16 thread block grid.

  • fvm_navier_stokes_step: Computes face mass fluxes (me, mw, mn, ms) via arithmetic face averaging, then evaluates FOU convective and central-differencing diffusive fluxes for both u and v. Writes u_new and v_new; IBM cells zeroed in place.
  • rhie_chow_source: PPE right-hand side assembly with Rhie–Chow face velocity interpolation. Corrects face velocities by the difference between the local pressure gradient and the cell-centred gradient interpolated to the face. Zeroes fluxes across IBM cell boundaries to enforce no-penetration.
  • velocity_correct: Applies the pressure gradient correction using central-difference stencils (p[P+1]−p[P−1])/(2·dx) at each interior cell. IBM cells re-masked by the BC manager after this step.

Three additional diagnostic kernels run at monitor intervals only: max_velocity (fused block-reduction for adaptive CFL, avoids a cp.hypot temporary array), check_nan (atomically sets a device-side int32 flag — deferred to monitor interval, eliminating one sync per step from the original design), and rms_div (masked RMS divergence excluding IBM cells).

Pressure Solver Backends

Three backends are available, selected by flags in poisson.py:

  • CuPy Krylov — GPU-native (default): Builds a CSR Poisson matrix once at startup. Solves A·p = −b using cupyx.scipy.sparse.linalg — CG for symmetric (cavity) or BiCGStab for open/asymmetric cases (airfoil, channel). Jacobi diagonal preconditioner. Internal solve in float64 for numerical stability, result cast to float32. Zero PCIe transfers during the time loop. O(√N) convergence versus O(N) for Jacobi iteration.
  • AmgX PCG+AMG: Algebraic multigrid preconditioned conjugate gradient via the AmgX library, wrapped in Python through ctypes. Fast convergence per iteration but requires 4 PCIe round-trips per solve (GPU→CPU→AmgX→CPU→GPU). Available as a fallback when CuPy Krylov is unavailable.
  • Red-Black SOR (fallback): Fully GPU-resident CUDA kernel. Red-Black ordering makes all updates in each half-sweep data-race-free. Optimal relaxation: ω = 2/(1 + sin(π/min(Nx,Ny))). Converges approximately 20× faster per iteration than the original Jacobi (100 SOR iterations ≈ 2,000 Jacobi iterations for N=200).

Host–Device Sync Budget

Minimising PCIe round-trips is critical on mobile GPU memory (6.44 GB). The original design issued three host-device synchronisations per step; the current implementation reduces this to one:

  • CFL adaptive dt — one unavoidable sync per step (scalar float cast from the max-velocity reduction).
  • NaN detection — eliminated from the hot loop. A device-side atomic int32 flag is only pulled to the host at monitoring intervals (default every 100 steps).
  • Stream.synchronize() barrier — removed entirely, enabling CUDA to pipeline consecutive kernel launches and hide launch latency.

Diagnostic reductions (RMS residual, RMS divergence, VRAM usage) are batched into a single Stream.synchronize() at the same monitor interval, adding one sync every N steps rather than every step.

Validation

  • Ghia et al. (1982) lid-driven cavity: Multi-Re sweep at Re = 100, 400, 1,000, and 3,200 on a 129×129 grid (dx = 1/128). Solver centerline velocity profiles are compared against the published tabulated reference data. The ghia_validation.py module automates the sweep, interpolates solver output onto the Ghia reference points, and generates comparison plots.
  • Plane channel (Poiseuille flow): The Re=400 channel preset recovers the analytical parabolic profile u(y) = (3/2)U∞[1−(y/H)²] to within the discretisation error on the 2,000×200 grid.
  • Kármán vortex street: The cylinder preset at Re=200 develops periodic vortex shedding with a Strouhal number consistent with experimental literature values (St ≈ 0.19) after the CFL ramp phase.

Code Structure

  • config.py — FlowPreset frozen dataclass + all five preset definitions. One-line change to switch cases.
  • gpu_kernels.py — Three CUDA RawKernel objects: NS predictor, Rhie-Chow source, velocity corrector.
  • poisson.py — Backend selection flags, CuPyPoissonSolver class, Red-Black SOR kernel.
  • gpu_csr_builder.py — Assembles the sparse CSR Poisson matrix on-GPU.
  • diagnostics.py — DiagnosticsManager: NaN flag kernel, fused max-velocity reduction, RMS divergence, CUDA event timing.
  • solver.py — Main fractional-step time loop with backend selection and adaptive time stepping.
  • geometry.py — IBM geometry factory: NACA profile generation, cylinder, rectangle, flat plate.
  • boundary_conditions.py — BC profiles indexed by preset bc_profile key.
  • ghia_validation.py — Automated Ghia 1982 multi-Re validation sweep.
  • tecplot_writer.py — Writes final flow field to Tecplot ASCII format for post-processing in ParaView or Tecplot 360.
