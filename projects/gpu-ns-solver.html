GPU-Accelerated 2D NS Solver

A 2D incompressible Navier–Stokes solver built from scratch in Python/CuPy with custom CUDA kernels — Chorin fractional-step, Rhie-Chow pressure correction, IBM geometry, and swappable Krylov pressure backends running entirely on GPU.

Context

This is a personal research and learning tool: a complete 2D incompressible Navier–Stokes solver written entirely from scratch in Python with CuPy, keeping all computation on the GPU. The motivation was to build a solver I fully understand at every layer — from the finite-volume flux assembly in CUDA to the pressure Poisson matrix construction in CSR format — to complement the OpenFOAM-based research work and develop fluency in GPU numerical computing.

The solver is structured around a FlowPreset dataclass: switching flow cases is a one-line change. All domain parameters, solver settings, geometry, and boundary condition profiles are encapsulated in a preset, so no other file requires editing when changing cases.

Numerical Method

The solver implements Chorin's fractional-step (projection) method on a uniform Cartesian staggered grid with finite-volume discretisation. The time-integration loop follows:

  1. Momentum predictor: Explicit Euler step solving the advection–diffusion equation without pressure. Convective fluxes use first-order upwind (FOU); diffusive fluxes use central differencing. Implemented as a CUDA RawKernel with per-cell metric scaling for variable mesh spacing.
  2. Rhie-Chow correction: Face velocities are reconstructed with a Rhie–Chow interpolation to suppress the checkerboard instability inherent to collocated pressure–velocity storage. The correction accounts for local pressure-gradient differences between face-interpolated and cell-centred values.
  3. Pressure Poisson equation: The PPE right-hand side (divergence of the predicted velocity field, scaled by ρ/dt) is assembled on-GPU. The system A·p = −b (A = negative discrete Laplacian, SPD) is solved by the configured backend (see below).
  4. Velocity corrector: Cell-centred velocities are corrected by the pressure gradient to enforce incompressibility: u ← u* − (dt/ρ)∇p.

IBM (immersed boundary method) masking zeroes velocities inside body cells after each predictor and corrector step. Local mesh refinement around the body and in the wake is supported through the mesh options dictionary.

CUDA Kernels

Three primary kernels are compiled at solver startup via cp.RawKernel with --use_fast_math:

fvm_navier_stokes_step

Momentum predictor. Computes face mass fluxes (me, mw, mn, ms) via arithmetic face averaging, then evaluates FOU convective and central-differencing diffusive fluxes for both u and v. Writes u_new and v_new; IBM cells zeroed in place.

rhie_chow_source

PPE RHS assembly with Rhie–Chow face velocity interpolation. Corrects face velocities by the difference between the local pressure gradient and the cell-centred gradient interpolated to the face. Zeroes fluxes across IBM cell boundaries.

velocity_correct

Applies the pressure correction. Updates u and v using central-difference pressure gradients (p[P+1]−p[P−1]) / (2·dx) at each interior cell. IBM cells are re-masked by the BC manager after this step.

Diagnostics kernels

Three auxiliary kernels: max_velocity (fused block-reduction for adaptive CFL, avoids cp.hypot temporary), check_nan (atomic flag, deferred to monitor interval), rms_div (masked RMS divergence excluding IBM cells).

Pressure Solver Backends

The pressure Poisson equation is the performance-critical step. Three backends are available, selected by flags in poisson.py:

  • 01
    CuPy Krylov — GPU-native (default) Builds a CSR Poisson matrix once at startup via build_poisson_csr_gpu. Solves A·p = −b using cupyx.scipy.sparse.linalg: CG for symmetric (cavity), BiCGStab for open/asymmetric (airfoil, channel). Jacobi diagonal preconditioner. Internal solve in float64 for numerical stability, result cast to float32. Zero PCIe transfers during the time loop. O(√N) convergence vs O(N) for Jacobi iteration.
  • 02
    AmgX PCG+AMG Algebraic multigrid preconditioned conjugate gradient via the AmgX library, wrapped in Python via ctypes (amgx_wrapper.py). Fast convergence per iteration but requires 4 PCIe round-trips per solve (GPU→CPU→AmgX→CPU→GPU). Recommended only when CuPy Krylov is unavailable.
  • 03
    Red-Black SOR (fallback) Fully GPU-resident CUDA kernel. Red-Black ordering makes all updates in each half-sweep data-race-free. Optimal relaxation: ω = 2/(1 + sin(π/min(Nx,Ny))). Converges ~20× faster per iteration than the original Jacobi (100 SOR iters ≈ 2000 Jacobi iters for N=200). Used when CuPy Krylov and AmgX are both disabled.

Host–Device Sync Budget

Minimising PCIe round-trips is critical for GPU solver performance. The original design issued three syncs per step; the current implementation reduces this to one:

Syncs per time step
CFL adaptive dt — cp.max(block_max)1 sync · unavoidable
NaN detection — deferred to monitor intervaleliminated from hot loop
Stream.synchronize() barrier — removedeliminated — enables pipelining
Total hot-loop budget1 sync/step

NaN checking uses a device-side int32 flag set atomically by a kernel; it is only pulled to the host at monitoring intervals (configurable, default every 100 steps). Diagnostic reductions (RMS residual, RMS divergence, VRAM usage) are batched into a single Stream.synchronize() at the same interval.

All presets share the same solver loop and kernel suite. The FlowPreset dataclass is frozen (immutable after construction), so preset parameters cannot be accidentally mutated during a run. CFL ramp parameters prevent impulsive-start pressure shocks by growing the time step from 0.001 to the target CFL over a configurable number of steps.

Validation

Ghia et al. (1982) lid-driven cavity: A multi-Re sweep at Re = 100, 400, 1000, and 3200 on a 129×129 grid (dx = 1/128) was run to compare solver centerline velocity profiles against the published tabulated data. The ghia_validation.py module automates this sweep, interpolates solver output onto the Ghia reference points, and generates comparison plots.

Plane channel (Poiseuille flow): The Re=400 channel preset recovers the analytical parabolic profile u(y) = (3/2)U∞[1−(y/H)²] to within the discretisation error on the 2000×200 grid.

Vortex shedding: The cylinder preset at Re=200 develops a Kármán vortex street with a Strouhal number consistent with literature values (St ≈ 0.19) after the CFL ramp.

Code Structure

  • config.py — FlowPreset dataclass + all five preset definitions. One-line switch to change cases.
  • gpu_kernels.py — Three CUDA RawKernel objects: NS predictor, Rhie-Chow source, velocity corrector.
  • poisson.py — Backend selection flags, CuPyPoissonSolver class, Red-Black SOR kernel.
  • gpu_csr_builder.py — Assembles the sparse CSR Poisson matrix on-GPU.
  • diagnostics.py — DiagnosticsManager: NaN flag, fused max-velocity, RMS divergence, CUDA event timing.
  • solver.py — Main fractional-step time loop.
  • geometry.py — IBM geometry factory: NACA profile, cylinder, rectangle, flat plate.
  • boundary_conditions.py — BC profiles indexed by preset name.
  • ghia_validation.py — Automated Ghia 1982 validation sweep.
  • tecplot_writer.py — Writes final flow field to Tecplot ASCII format for post-processing.
